# Runbook: Caddy / TLS configuration

HTTPS termination in production is handled by Caddy, running directly on
the Droplet host (not containerized) in front of the `ear-candy` container's
published port. Caddy auto-provisions and renews a Let's Encrypt certificate
for the configured domain with no manual TLS setup required.

## Source of truth

`infra/Caddyfile.template` is the versioned source of truth for the live
`/etc/caddy/Caddyfile` on the Droplet. `scripts/setup-droplet.sh` renders it
(substituting `__DOMAIN__` for the real domain) during initial provisioning
— see that script's "Configure Caddy" step.

Previously the Caddy config was generated by an inline heredoc in the setup
script and never checked in anywhere, which let the live config silently
drift from what the script would produce on a fresh run: the live Droplet
was hand-corrected to proxy to port 3000 (the app's real port) while the
script still generated `localhost:3001`, and nobody noticed until it was
checked directly (issue #58). Rendering from a single checked-in template
closes that gap — there's now something for a live edit to diff against.

## If you ever hand-edit `/etc/caddy/Caddyfile` on the Droplet

Back-port the change to `infra/Caddyfile.template` in this repo (swapping
the real domain back out for `__DOMAIN__`) in the same sitting. If you
don't, the next fresh Droplet provisioned from `setup-droplet.sh` will
silently regenerate the old, un-hand-edited config — exactly the failure
mode this file exists to prevent.

## Verifying the live config matches the template

```bash
ssh earcandy "cat /etc/caddy/Caddyfile"
```

Compare against `infra/Caddyfile.template` with the real domain substituted
in for `__DOMAIN__`. They should match exactly.
